# Credits, Research Acknowledgements, and Provenance

Code Composer is independently implemented. This file records external research, software, and data resources that materially informed its design, especially the bowed-string/violin work in S3-S13, the acoustic-piano release hardening in S14, ensemble-interaction work in S15, plucked-bass acoustic-fidelity work in S16, percussion acoustic-fidelity work in S17, drum-kit room/performance integration in S26, and the S27 drum-authenticity / hi-hat-state chain through S27-L, plus the S28 acoustic-piano naturalism chain through S28-H. S28-A-H are independent extensions of the existing S14/v1.16 piano and performance models and introduce no new third-party code, audio, measurements, or datasets. S28-G/H preserve modeled three-string treble unisons while changing only independently implemented deterministic synthesis/control behavior.

This document is an acknowledgement/provenance record, not a substitute for third-party license texts. If Code Composer later bundles third-party source code, measurement assets, impulse responses, recordings, models, or other redistributable artifacts, their exact license and attribution requirements must also be carried in an asset-local notice or `THIRD_PARTY_NOTICES.md`.

## Software and implementation references

### Julius O. Smith — Physical Audio Signal Processing

Julius O. Smith's public physical-modeling material on digital waveguides and bowed strings informed the high-level decomposition used in S5 and later slices: traveling-wave string state, a nonlinear bow/string interaction, losses in the feedback loop, and a separate body/radiation stage.

- Author: Julius O. Smith III
- Resource: *Physical Audio Signal Processing*
- Relevant topic: bowed strings / bow-string scattering junction / digital waveguides
- Project usage: conceptual and algorithmic reference only; no source code copied.
- URL: https://ccrma.stanford.edu/~jos/pasp/

### STK — The Synthesis ToolKit

STK's `Bowed` instrument was consulted as a public reference for a practical real-time bowed-string digital-waveguide architecture using propagation delays, nonlinear bow interaction, string loss, and body filtering.

- Project: The Synthesis ToolKit in C++ (STK)
- Original authors/maintainers: Perry R. Cook, Gary P. Scavone, and contributors
- Project usage: architecture/reference comparison only; Code Composer does not vendor STK code.
- STK's published license is permissive and requires retaining its notice when redistributing STK software; no STK software is redistributed here.
- URL: https://ccrma.stanford.edu/software/stk/

### Faust Physical Modeling Libraries

Faust physical-modeling resources were consulted for the decomposition of violin bow, bowed string, bridge, and body components and for comparison with established digital-waveguide practice.

- Project: Faust / Faust Libraries, GRAME-CNCM
- Relevant library: `physmodels.lib`
- Project usage: conceptual/reference comparison only; Code Composer does not vendor or compile Faust library source.
- Licensing note: licensing in the wider Faust Libraries varies by file/contributor, and an open upstream issue has specifically requested an explicit license declaration for `physmodels.lib`. Code Composer therefore treats this resource strictly as a reference unless a future integration audits the exact upstream file/version and license.
- URL: https://faustlibraries.grame.fr/libs/physmodels/

### S27-H / S27-I / S27-J / S27-K stateful hi-hat continuation

S27-H, S27-I, S27-J, and S27-K add no new third-party implementation dependency or bundled research asset. They extend the S27-B hi-hat causal model with independently implemented time-domain state handling: discrete closure/choke, explicit continuous pedal-openness curves, persistent pedal state, and pedal-coupled later stick strikes. No publication code, FDM mesh, measurement, audio recording, pedal-controller dataset, or fitted commercial-instrument response is redistributed.

S27-K R1 changed only the independently implemented collision micro-contact approximation used by control-derived chick/splash audio to remove a sparse digital crackle artifact. Production listening then rejected the denser additive texture as a felt/fabric-like noise bed. S27-K R2 removes that additive control-foot collision layer and relies on the existing independently implemented two-plate/contact response with bounded output calibration. Neither R1 nor R2 introduces a new external research dependency or redistributable third-party asset.

S27-B R1 reopens the underlying two-cymbal strike source after production listening identified the same class of perceptual failure in the original state collision layer. The new compact approximation still follows the already-cited two-cymbal / impacted-plate causal references, but replaces direct normalized broadband collision audio with finite re-contact forces that excite a dense inharmonic modal plate field. No publication solver, mesh, measured modal table, recording, IR, or fitted commercial-instrument response is copied or redistributed.

## Attribution policy for future measured assets

A future measured-instrument resource may only be bundled after all of the following are recorded:

1. exact source record and persistent identifier (preferably DOI);
2. original authors/creators and institutional attribution;
3. exact file identity and checksum;
4. measurement meaning and units (for example force-normalized bridge velocity);
5. source instrument identifier/anonymization constraints;
6. license and redistribution permission;
7. required citation or acknowledgement text;
8. preprocessing performed by Code Composer before fitting;
9. fitted-profile version and source-data hash;
10. whether the resource may be used commercially, modified, and redistributed.

If those conditions are not satisfied, Code Composer may use the source as a research reference but must not ship the underlying asset or label a factory preset as a measured reproduction of that instrument.
