# Code Composer v1.18.0

v1.18.0 is the first release of the CR00–CR08 Composer-first rebuild.

## Highlights

The canonical composition path is now:

`User intent → Song → Execution Plan → Performance Score → instrument/performance realization → resolved IR → render/export`

The agent or user remains the musical authority. Runtime contracts preserve explicit decisions, validate objective correctness and reproduce them deterministically; analyzers do not decide whether music is aesthetically good.

### Composer-first authoring

- Minimal `code-composer-song/v1` authored state.
- Arbitrary track IDs and musical functions instead of a privileged six-role authoring grammar.
- Deterministic Execution Plan lowering with explicit instrument/preset resolution and provenance.
- Performance Score as the exact authority for notes, drum hits, voicings, timing, articulation, supported controls and mix intent.

### Revision, preview and QA

- Targeted revision plans and records with exact before/after fingerprints.
- Deterministic cached preview/range rendering while preserving stateful-instrument timeline correctness.
- Hard integrity failures are separated from descriptive musical evidence.
- No aggregate aesthetic score, automatic aesthetic acceptance or analyzer-authored musical revision.

### Orchestration

CR07 verified the new track-function model across band, chamber and electronic dogfoods. It also adds explicit authored drum-hit semantics and rejects pitched-note percussion surrogates.

### Resonant plucked instruments

CR08 adds the opt-in `resonant_pluck` engine and `resonant_pluck.zither_bright` preset.

For resonant engines, authored note duration is the **gate/excitation duration**, not a forced sample-buffer endpoint. The engine owns its natural physical tail and reports the maximum additional lifetime through `tail_seconds(patch)`. This fixes the class of abrupt plucked-string tail cuts without adding song-specific ornament-to-tail lookup tables.

## Breaking change

The historical CompositionBrief / seed-first / fixed `lead/topline/pad/bass/arp/drums` authoring architecture is now a pre-refactor reference. v1.18.0 intentionally does not add a migration or compatibility layer for that authoring surface.

Validated DSP/instrument engines, deterministic rendering, MIDI, exchange/delivery, provenance and contract rigor are retained.
